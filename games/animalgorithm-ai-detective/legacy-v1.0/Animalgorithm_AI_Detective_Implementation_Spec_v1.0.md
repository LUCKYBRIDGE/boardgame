## 0. 문서의 근거와 범위

### 0.1 제공 자료에서 직접 가져온 핵심 구조
제공된 MIT AI 언플러그드 분석 자료에 따르면 Animal-gorithm의 기본 구조는 다음과 같다.

- 1명이 숨겨진 분류 기준을 가진 **알고리즘 역할**을 맡는다.
- 나머지 플레이어는 동물 카드를 하나씩 입력 데이터처럼 제시한다.
- 알고리즘 역할은 각 입력을 **True / False**로만 판정한다.
- 플레이어는 분류 결과를 관찰해 공통 특징을 찾고 **숨겨진 분류 규칙을 역추적**한다.
- 자료에는 동물 카드 30장, 빈 카드 도안, 비밀 카테고리 카드가 제시되어 있다.
- 보드게임화 제안으로는 동물 특성 카드, 규칙 가림판, 분류 성공 토큰, 쿼리 시 자원 소모를 이용한 효율적 질문 설계가 제안되어 있다.

### 0.2 이 문서에서 새로 정한 프로젝트 규칙
아래 항목은 제공 자료를 그대로 복제한 것이 아니라, 실제 제품/교구로 구현하기 위해 본 프로젝트에서 제안하는 설계다.

- 카드 크기, 안전 여백, 인쇄 규격
- 정확한 승리 조건과 점수 방식
- 난이도 레벨
- 데이터 스키마
- 파일 구조
- 접근성 색상 규칙
- 테스트 기준
- 레포지토리 구성

### 0.3 저작권/라이선스 주의
제공 자료만으로는 MIT 원본 카드의 **상업적 재배포/수정 허용 범위가 확인되지 않는다.**

따라서 실제 배포용 제품에서는:

2. 동물 일러스트와 UI는 프로젝트 자체 자산으로 새로 제작할 것
3. 외부 배포 전 원본 활동의 라이선스/출처 표기 조건을 별도 확인할 것

# 1. 게임의 교육 목표

## 1.1 핵심 AI 개념
이 게임은 다음 개념을 **규칙 설명이 아니라 플레이 행동으로 경험**하게 만드는 것이 목적이다.

1. **Feature Extraction / 특성 추출**
   - 동물을 이름으로만 보지 않고 날개, 다리 수, 서식지, 몸의 특징 등으로 분석한다.

2. **Classification / 분류**
   - 입력된 데이터가 어떤 기준에 의해 True 또는 False로 라벨링되는지 경험한다.

3. **Decision Rule / 분류 규칙**
   - 여러 데이터의 결과를 관찰해 숨어 있는 규칙을 추론한다.

4. **Query Efficiency / 효율적인 데이터 탐색**
   - 아무 카드나 계속 내는 것이 아니라, 규칙을 가장 빨리 구별할 수 있는 카드를 선택한다.

5. **AI는 의미를 '안다'기보다 규칙에 따라 판정한다**
   - 알고리즘 역할은 감정이나 상식으로 판정하지 않고 비밀 규칙만 기계적으로 적용한다.

---

# 2. 핵심 게임 원칙

## 2.1 가장 중요한 설계 원칙
이 게임은 단순 스무고개와 달라야 한다.

플레이어는 다음처럼 직접 질문하지 않는다.

- "날개가 있나요?"
- "물에 사나요?"
- "다리가 4개인가요?"

대신 **동물 카드 자체를 데이터 입력(Query)** 으로 사용한다.

예:

- 오리 카드 입력 → True
- 고양이 카드 입력 → False
- 펭귄 카드 입력 → True
- 독수리 카드 입력 → False

이 결과를 보고 플레이어가 규칙을 추론해야 한다.

이 제한이 있어야 게임이 **머신러닝 분류 실험**처럼 작동한다.

# 4. 동물 카드 데이터 설계

## 4.1 카드마다 반드시 구조화할 특징
MVP에서는 특징 종류를 너무 많이 쓰지 않는다.

### 권장 핵심 Feature 8종
1. **날개**: 있음 / 없음
2. **다리 수**: 0 / 2 / 4 / 6 / 8+
3. **주 서식지**: 육지 / 물 / 양쪽 / 공중 중심
4. **몸의 덮개**: 털 / 깃털 / 비늘 / 외골격 / 매끈한 피부
5. **크기**: 작음 / 중간 / 큼
6. **먹이 성향**: 초식 / 육식 / 잡식
7. **척추동물 여부**: 예 / 아니오
8. **체온 조절**: 온혈 / 변온

### 저학년용 단순 모드
초등 3학년 이하에서는 다음 5개만 노출하는 것을 권장한다.

- 날개
- 다리 수
- 사는 곳
- 크기
- 몸의 겉모습

## 4.2 카드에서 Feature를 모두 보여줄 것인가?
**기본 모드: 보여준다.**

이 게임의 핵심은 생물 지식 암기가 아니라 **특성 비교와 규칙 추론**이다.  
플레이어가 "펭귄이 온혈인가?"를 몰라서 틀리는 게임이 되면 AI 교육 목표에서 벗어난다.

따라서 각 동물 카드 하단에 **아이콘형 Feature 바**를 제공한다.

# 5. 비밀 규칙 설계

## 5.1 난이도 1 — 단일 Feature
예:
- 날개가 있다.
- 다리가 4개다.
- 물에서도 산다.
- 몸에 털이 있다.
- 크기가 크다.

**권장 대상:** 초등 3~4학년, 첫 플레이

## 5.2 난이도 2 — AND 조합
예:
- 날개가 있고 물에서 산다.
- 다리가 4개이고 털이 있다.
- 크기가 작고 날개가 없다.

**권장 대상:** 초등 4~6학년

## 5.3 난이도 3 — AND / OR 조합
예:
- 날개가 있거나 물에서 산다.
- 다리가 4개이고, 크기가 중간 이상이다.
- 털이 있거나 깃털이 있다.

**권장 대상:** 숙련 플레이

## 5.4 MVP에서 금지할 규칙
초기 버전에서는 다음은 사용하지 않는다.

- "귀여운 동물"
- "무서운 동물"
- "사람에게 인기 있는 동물"
- "빨리 달리는 동물"
- 생물학적으로 애매하거나 논쟁 가능한 규칙
- 동물 이름 자체를 직접 지칭하는 규칙
- 예외 규칙("단, 펭귄은 제외")
- 너무 희귀한 조건

# 6. 좋은 규칙 카드의 자동 검증 조건

비밀 규칙은 덱 전체에서 너무 많은 카드 또는 너무 적은 카드에 적용되면 재미가 급격히 떨어진다.

## 6.1 권장 분할 범위
30장 기준:

- True: **8~22장**
- False: **8~22장**

가능하면:
- True 10~20장
- False 10~20장

을 권장한다.

## 6.2 규칙 품질 체크
각 규칙은 다음을 통과해야 한다.

- [ ] 모든 카드에 대해 판정이 100% 결정적이다.
- [ ] 교사/학생에 따라 판정이 달라지지 않는다.
- [ ] 최소 8장 이상이 True다.
- [ ] 최소 8장 이상이 False다.
- [ ] 3~6회의 좋은 Query로 추론 가능한 단서가 생긴다.
- [ ] 다른 규칙과 사실상 동일한 결과를 만들지 않는다.

# 7. 기본 게임 규칙

## 7.1 준비
1. 동물 카드 30장을 잘 섞어 테이블 중앙에 놓는다.
2. 한 명이 **알고리즘 마스터**가 된다.
3. 알고리즘 마스터는 비밀 규칙 카드 1장을 뽑아 가림판 뒤에 놓는다.
4. Query 토큰 10개를 중앙에 놓는다.
5. True / False 영역을 테이블 양쪽에 배치한다.

## 7.2 한 턴
현재 플레이어는 공개된 동물 카드 또는 손에 든 동물 카드 중 하나를 선택해 알고리즘 마스터에게 제시한다.

이 행동이 **Query**다.

알고리즘 마스터는 규칙에 따라:

- True → True 영역
- False → False 영역

에 카드를 놓는다.

Query 토큰 1개를 제거한다.

## 7.3 규칙 추측
플레이어는 자신의 턴에 Query 대신 규칙을 추측할 수 있다.

예:
> "날개가 있고 물에서 사는 동물이다."

### 정답
즉시 라운드 승리.

### 오답
- Query 토큰 2개 추가 소모
- 해당 플레이어는 다음 1턴 동안 재추측 불가

## 7.4 라운드 종료
다음 중 하나가 발생하면 종료한다.

1. 누군가 비밀 규칙을 맞힘
2. Query 토큰이 모두 소진됨

토큰이 모두 소진될 때까지 아무도 맞히지 못하면 알고리즘 마스터가 승리한다.

# 8. 점수 규칙

단발 플레이에서는 "먼저 맞힌 플레이어 승리"만으로 충분하다.

여러 라운드를 할 때는 다음 방식을 권장한다.

## 탐정 점수
정답을 맞힌 플레이어:

**남은 Query 토큰 + 규칙 난이도 보너스**

- 난이도 1: +1
- 난이도 2: +2
- 난이도 3: +3

## 알고리즘 마스터 점수
아무도 맞히지 못함:
- +5점

8회 이상 Query를 사용한 뒤에야 정답이 나옴:
- +2점

# 9. 협력 수업 모드

학교 수업에서는 경쟁보다 이 모드를 우선 권장한다.

## 목표
학급 전체가 **10 Query 이내**에 비밀 규칙을 찾아낸다.

## 진행
- 4명 팀 구성
- 매 턴 팀이 30초간 상의
- 한 장만 Query
- 팀 기록지에 다음 내용 작성:
  - 입력 카드
  - 결과
  - 현재 가설
  - 다음 카드를 고른 이유

## 수업 후 발문
- "왜 그 동물을 다음 Query로 골랐나요?"
- "어떤 카드가 규칙을 가장 잘 구별해 줬나요?"
- "AI는 동물의 이름을 이해해서 분류한 걸까요?"
- "특징 하나가 바뀌면 결과도 바뀔까요?"
- "우리가 잘못된 Feature를 쓰면 어떤 일이 생길까요?"

# 10. 카드 디자인 규격

## 10.1 공통 인쇄 규격
**표준 카드 크기:** 63 × 88 mm

권장:
- Bleed: 3 mm
- Trim: 63 × 88 mm
- Safe Area: 가장자리에서 4 mm 이상
- 인쇄 해상도: 300 dpi 이상
- 래스터 최소 작업 크기: 약 744 × 1039 px 이상
- 원본은 SVG / PDF 벡터 우선
- PNG 출력본은 투명 배경 허용
- 텍스트는 최종 인쇄 PDF에서 윤곽선 변환 또는 폰트 임베드

## 10.2 동물 카드 레이아웃
세로 카드 기준:

### A. 상단 14 mm
- 카드 번호
- 동물 이름
- 난이도 아이콘(필요 시)

### B. 중앙 약 48 mm
- 동물 일러스트
- 배경은 단순
- 실제 특징이 명확히 보이는 자세
- 장식 요소 최소화

### C. 하단 약 22 mm
Feature 아이콘 바

권장 배열:
- 날개
- 다리 수
- 서식지
- 몸 덮개
- 크기

고학년 확장에서는 뒷면 또는 상세 모드로:
- 먹이
- 척추동물
- 체온

## 10.3 텍스트 최소 크기
실물 인쇄 기준:
- 카드명: 15~18 pt
- Feature 라벨: 최소 10.5 pt
- 규칙 카드 본문: 13 pt 이상
- 교사용 작은 설명: 9 pt 이상

# 11. 컬러 시스템

색상만으로 의미를 구별하지 않는다.

## 권장 팔레트
| 용도 | 색상 | HEX | 추가 기호 |
|---|---|---|---|
| True | 녹색 | #18794E | ✓ |
| False | 적색 | #B42318 | × |
| Query | 파랑 | #2F6BFF | ? |
| Secret Rule | 보라 | #6B4EFF | 🔒 또는 열쇠 아이콘 |
| Neutral BG | 밝은 회색 | #F7F8FA | - |
| Text | 거의 검정 | #111827 | - |

### 접근성 원칙
- True/False는 반드시 **색 + 아이콘 + 텍스트**를 함께 사용
- 빨강/초록만으로 구별하지 않음
- 카드 바탕과 텍스트 명도 대비 확보
- 아이콘은 최소 6 mm 이상

# 12. 일러스트 지침

## 12.1 스타일
- 초등 교구에 적합한 평면/반평면 일러스트
- 실제 동물의 특징을 알아볼 수 있어야 함
- SD 캐릭터처럼 특징이 왜곡될 정도의 과장은 피함
- 동일 종 카드 간 표현 방식 일관성 유지

## 12.2 금지
- 실제 Feature를 가리는 의상/소품
- 지나치게 복잡한 배경
- 애매한 다리 수
- 날개가 가려지는 구도
- 물/육지 여부를 배경만으로 암시하는 방식

**Feature는 일러스트가 아니라 데이터 아이콘에서 최종 확인 가능해야 한다.**

# 13. 비밀 규칙 카드 디자인

앞면:
- 난이도
- 규칙 문장
- 논리식
- True 예시 2장
- False 예시 2장
- 규칙 ID

예:

> 날개가 있고 물에서도 산다.

`wings == true AND habitat IN [water, both]`

뒷면:
- 모두 동일한 그래픽
- 규칙 내용이 비치지 않게 고대비 패턴 사용

```ts
function evaluateRule(animal, rule) {
  // conditions를 순회하여 판정
}
```

## 필수 요구사항
- 같은 `animal + rule` 조합은 항상 같은 결과
- 카드 UI와 판정 엔진이 동일한 Feature 데이터를 사용
- 사람 눈에 보이는 아이콘과 내부 데이터가 불일치하면 빌드 실패 처리
- 규칙별 True/False 개수를 빌드 시 자동 검사

# 19. 반드시 피해야 할 설계 실수

1. **동물 퀴즈 게임으로 변질**
   - 생물 지식 자체를 묻지 않는다.

2. **직접 질문 허용**
   - "날개 있어?"라고 묻기 시작하면 AI 분류 실험 구조가 약해진다.

3. **규칙이 너무 주관적**
   - 귀여움, 빠름, 위험함 등은 피한다.

4. **True/False가 극단적으로 한쪽에 몰림**
   - 규칙 추론이 불가능하거나 너무 쉬워진다.

5. **아이콘과 내부 데이터 불일치**
   - 가장 심각한 콘텐츠 오류.

6. **복잡한 논리식 남발**
   - 초등용에서는 `AND`, `OR` 정도까지만 사용.

7. **원작의 시각 자산을 그대로 복제**
   - 라이선스 확인 전에는 자체 디자인을 사용.

# 20. 출시 전 Acceptance Criteria

## 콘텐츠
- [ ] 동물 카드 최소 30장
- [ ] 비밀 규칙 최소 18장
- [ ] 모든 규칙이 자동 판정 가능
- [ ] 모든 규칙의 True/False가 각각 최소 8장 이상
- [ ] 모든 Feature가 카드에 시각적으로 표시됨

## 게임
- [ ] 5분 이내 룰 설명 가능
- [ ] 20분 안에 3라운드 가능
- [ ] 첫 플레이 학생이 2라운드부터 스스로 진행 가능
- [ ] 규칙 추측 시 관찰된 데이터를 근거로 말하게 됨
- [ ] "좋은 Query"와 "나쁜 Query"의 차이를 경험할 수 있음

## 교육
플레이 후 학생이 아래 질문 중 3개 이상에 답할 수 있으면 성공으로 본다.

- AI가 동물을 무엇을 보고 분류했나?
- Feature란 무엇인가?
- 같은 결과를 내는 카드들의 공통점은 무엇인가?
- 어떤 Query가 규칙을 알아내는 데 도움이 되었나?
- 잘못된 Feature를 쓰면 어떤 문제가 생길까?

# 21. v1.0의 핵심 결론

**동물고리즘 – AI 탐정은 '스무고개'처럼 보이지만, 실제 구현에서는 반드시 '카드를 입력하고 결과 라벨을 관찰하여 규칙을 역추론하는 게임'으로 유지해야 한다.**

첫 프로토타입은 복잡하게 만들 필요가 없다.

> **30장 동물 카드 + 18장 규칙 카드 + True/False 영역 + Query 토큰**

이 네 가지가 MVP의 중심이다.

게임성이 부족하면 구성물을 늘리는 것이 아니라 먼저:
1. Query 제한
2. 규칙 난이도
3. 점수
4. 협력/경쟁 구조

를 조정한다.

그래픽 완성보다 **데이터 구조와 규칙 품질을 먼저 확정**하는 것이 이 프로젝트의 핵심 구현 원칙이다.
